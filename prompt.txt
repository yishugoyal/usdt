Design and implement a **production-grade USDT-to-INR sell-to-company platform** called:

# RupeeBridge

The platform allows eligible users to sell supported USDT to the company and receive INR into their verified bank account.

This is a **company-to-user transaction platform, not a peer-to-peer marketplace**.

The company is the counterparty for every transaction.

# 3. USER KYC REQUIREMENT

Do **not** create a user-facing KYC submission workflow.

Do not create:

* KYC document upload screens
* User KYC application forms
* User KYC approval/rejection screens
* User identity-document dashboards
* User-facing KYC document management
* User-facing KYC verification queues

The primary user experience should not require the user to manually complete a traditional KYC workflow inside RupeeBridge.

However, do **not** interpret this as permission to bypass applicable AML, sanctions, tax, banking, identity, reporting, or other legal obligations.

The system must support a configurable compliance architecture so that legally required checks can be performed through approved providers or operational processes when applicable.

If the selected business model or jurisdiction requires identity verification before a transaction, the transaction must be blocked until the required verification has been completed.

Never claim that the platform is legally compliant merely because the KYC screens were removed.

# 6. USER ACCOUNT SYSTEM

Implement secure user registration.

User workflow:

1. Register with email and mobile number.
2. Verify email.
3. Verify mobile number.
4. Enable MFA.
5. Complete required account information.
6. Add a bank account.
7. Complete required bank-account verification.
8. Request a live USDT/INR sell quote.
9. Review quote.
10. Accept transaction terms.
11. Create sell order.
12. Receive deposit instructions.
13. Send USDT.
14. Wait for blockchain confirmation.
15. System performs automated risk/compliance checks where applicable.
16. Order becomes eligible for settlement.
17. INR payout is initiated.
18. User receives transaction receipt.

Do not insert a traditional user KYC application step into this workflow.
